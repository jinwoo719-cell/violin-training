# 🎻 바이올린 연습 도우미 — MVP

레슨 받는 학생이 집에서 혼자 연습할 때, **지판 어디를 짚어야 하는지** 보여주고
**실제로 어떻게 짚었는지** 악보 위에 겹쳐서 돌려주는 앱.

---

## 지금 되는 것

**화면 ① 연습 가이드**  ← **가로로 든 휴대폰** 기준 (844×390 에 스크롤 없이 들어감)

- 맨 위에 악보 한 줄 — 조표 · 임시표 · 마디선 · **슬러**
- 지판 좌우에 **스크롤·페그박스**와 **몸통·f홀·브리지** — 전부 사진 (악기별로 교체 가능)
- 오른쪽 **다음 음 안내** — 계이름 · 손가락 · 활 방향 · 포지션 ·
  **손 사진에서 짚을 손끝이 빨갛게**
  (손 사진은 너트가 오른쪽이라 **왼쪽부터 4·3·2·1**입니다 — 검지가 너트 쪽)
- **노드 배속 0.5~3.0배** (펌프·DJMax 방식) — 바에서 바로 조절, 다음에도 기억함
- **판정 자리(리셉터)** — 리듬게임처럼 판정선에 착지 자리가 그려져 있고,
  차례가 오면 그 자리가 켜집니다
- **저절로 시작하지 않습니다.** 녹음을 켠 뒤 **[▶ 시작]** 을 눌러야 돕니다 —
  그래야 박자가 녹음과 맞습니다. 끝나면 멈추고 다시 ▶ 를 기다립니다
- **준비 시간 + 메트로놈 카운트인** (노래방처럼) — ▶를 누르면
  준비 시간(없음/3/5/7/10/15초, 바에서 바로 조절) 동안 큰 숫자가 세어지고,
  이어서 **똑 · 똑 · 똑 · 똑** 네 박(첫 박은 높은 소리) 뒤에 첫 음이 옵니다
- **🔊 시범 듣기** — 켜면 떨어지는 노드와 **함께** 악보가 소리로 납니다.
  녹음 전에 "이렇게 들려야 한다"를 먼저 귀에 넣습니다
- **계이름은 그 음이 쓰는 줄 바로 아래**에, 그 줄 색으로.
  아래 한 줄에 몰아 적으면 줄이 여럿일 때 어느 줄 이름인지 알 수 없습니다
- **화면 폭에 맞춰 커집니다.** 예전에는 880px 에서 멈춰서 PC 에서 가운데만
  좁게 놓였습니다. 이제 넓은 화면에서는 키우되, **화면 높이의 55% 를 넘지
  않게** 합니다 — 가이드가 화면을 다 먹으면 아래 [분석하기] 가 밀려납니다
  (폰 가로에서는 원래 1배를 안 넘으므로 그대로입니다)
- 스크롤·**몸통**·손은 전부 사진 (`assets/`). 몸통 사진은 f홀·브리지·줄이
  실제 간격 그대로라, 사진 속 줄을 지판의 줄에 맞추면 한 줄로 이어져 보입니다
- **브리지는 지판 옆이 아니라 안내 패널에 있습니다** — 지판은 *어디를 짚나*,
  브리지는 *어느 줄을 켜나*. 다른 정보라 자리를 나눴고, 그만큼 지판이 넓어집니다
- **지판은 이번 악보가 쓰는 만큼만** 보여줍니다. 늘 190mm 를 그리면
  낮은 자리만 쓰는 악보가 왼쪽 구석에 몰려 붙습니다
- **지금 음표 켜기** — 악보에서 연주할 음표가 활 방향 색으로 바뀝니다
- 색이 곧 활 방향 (파랑 ⊓ 다운 / 주황 ∨ 업). 슬러 하나 = 활 한 번
- 노드가 **지판의 실제 mm 자리**로 떨어짐. 숫자는 손가락 번호
- **네 줄(G·D·A·E)을 다 그리고 연주하는 줄만 밝게** — 다른 줄은 손가락 자리만 흐리게
- 지금 몇 포지션인지 계속 표시, 손 옮기는 자리에 점선

**녹음 — 버튼 하나입니다**

```
[● 시작 + 녹음]  ← 이거 하나
     마이크 · 메트로놈 · 가이드가 동시에 시작합니다
     끝나면 녹음이 아래에 담깁니다 (분석은 원할 때만)
```

예전에는 ①마이크 켜고 ②가이드 시작을 **사용자가 순서대로** 눌러야 했습니다.
순서가 틀어지면 박자가 어긋나 분석이 통째로 무의미해졌습니다.
같은 클릭에서 시작하면 어긋날 수가 없습니다.

**어떻게 했나** — `st.components.v1.html` 은 한쪽으로만 말합니다(파이썬 → 화면).
그래서 화면 안에서 녹음한 소리를 파이썬으로 되돌릴 길이 없었고, 그게 버튼이
갈라져 있던 진짜 이유였습니다. **커스텀 컴포넌트**(`guide_component/`)로 바꾸니
길이 생겼습니다.

```
파이썬 ──html──▶ 껍데기 iframe ──srcdoc──▶ 가이드 (마이크·녹음)
   ▲                                          │
   └──────── WAV(base64) ◀── postMessage ─────┘
```

- 마이크 권한은 스트림릿이 컴포넌트 iframe 에 `allow="microphone"` 을 붙여 주고,
  껍데기가 안쪽까지 넘겨줍니다
- WAV 는 **브라우저에서** 만듭니다 (`toWav`) — 그래서 `analyze.py` 는 한 줄도
  안 고쳤습니다
- 가이드 HTML 은 그대로라, `데모_*.html` 을 혼자 열어도 똑같이 돕니다
  (`parent !== window` 일 때만 위로 올려보냅니다)

**분석은 자동이 아닙니다.** 여러 번 연주해 보고 마음에 드는 것 하나만
[분석하기] 하면 됩니다. 다시 [● 시작 + 녹음] 을 누르면 녹음이 새것으로 바뀝니다.

- 긴 설명은 **[❔ 연습 방법]** 뒤로 접었습니다. 연습 중에는 아무도 안 읽습니다.
  대신 **처음 오면 한 줄을 펴 둡니다** — 접기만 하면 초보자가 길을 잃습니다
- **분석해도 화면이 바뀌지 않습니다.** 그 자리 오른쪽에 점수 넷(종합·음정·박자·활)이
  뜨고, 더 보고 싶을 때만 **[자세히 보기 →]** 로 리포트에 갑니다
- 시범 연주는 두 갈래였는데 하나로 정리했습니다 — 소리만 듣기는 [❔ 연습 방법] 안에,
  떨어지는 노드와 **함께** 듣기는 가이드 바의 [🔊 시범 듣기]

**화면 ② 분석 리포트**

정보의 순서가 이 화면의 전부입니다.

1. **종합 점수** (음정 50% · 박자 30% · 활 20%) + 지표 넷
2. **악보 + 음별 표** — 표의 열이 위 악보의 음표와 **같은 가로 좌표**
3. **음 하나 안에서의 움직임** (궤적)
4. **가장 취약한 음 TOP 3** · 분석 코멘트 · 음정 분포

- 표의 아무 열이나 누르면 **그 부분 내 연주**가 다시 들림
- 재생 중 세로선 하나가 악보·표·궤적을 함께 지나감

**화면 ③ 내 악보**

교본 악보를 그대로 불러오는 기능은 **넣지 않았습니다.**
**내가 적은 것**과 **내가 가진 악보를 내가 찍은 것**만 다룹니다.

세 갈래가 전부 **같은 글 한 줄**로 모입니다 — 어느 길로 들어왔든 손으로 고칠 수 있게.

```
   ✍️ 직접 적기 ─┐
   📷 사진      ─┼→  "라 시 도♯5 레 …"  →  악보 미리보기  →  연습하기
   📄 MusicXML  ─┘
```

- 적는 법: `도 레 미 파 솔 라 시` (고정도) · `A B C…` · `도#` `레b` ·
  `라4` (옥타브, 안 적으면 앞 음에서 가장 가까운 쪽) · `라*2` 두 박 · `라/2` 반 박
- **🔊 들어보기** — 적은 악보를 정확한 음정·박자로 들려줍니다.
  악보를 잘못 적었으면 **눈보다 귀가 먼저 알아냅니다**
- **사진은 저장하지 않습니다** — 인식할 때 한 번만 쓰고 바로 버립니다
  (Gemini 키를 넣으면 동작. 키도 저장하지 않습니다)
- 조표는 적은 음들로 **짐작해서** 미리 골라 둡니다 (가장 적게 붙는 조표)
- 줄은 자동 — 한 줄 안에서 끝나면 그 줄, 안 되면 음마다 가장 낮은 자리
- **줄을 넘나드는 악보도 됩니다** — 쓰는 줄이 전부 밝아지고,
  노드에 줄 이름이 붙고, 착지점이 그 줄 위에 찍힙니다

**연습 종류** — 장조 / 자연단조 / 화성단조 / 가락단조 × G·D·A·E현 ·
데타셰 / 2음 슬러 / 4음 슬러 · BPM 40~120 · 그리고 **내가 넣은 악보**

**포지션 고르기** — `1포지션`(기본) · `3포지션` · `1 → 3포지션 (손 옮기기)`

기본은 **1포지션**입니다. 손을 옮기는 것(시프팅)은 나중에 배우는 기술이라,
처음부터 1→3 을 섞어 주면 배우는 순서가 뒤집힙니다.

한 포지션을 고르면 **손을 옮기지 않습니다.** 그 자리에서 안 닿는 음은
**옆 줄로 넘어가서** 짚습니다 (손은 그대로, 활만 옮김). 그래서

```
A장조 1포지션   라4·A0 시4·A1 도♯5·A2 레5·A3 미5·A4 | 파♯5·E1 솔♯5·E2 라5·E3
A장조 3포지션   라4·D2 시4·D3 도♯5·D4 | 레5·A1 미5·A2 파♯5·A3 솔♯5·A4 | 라5·E1
A장조 1→3       라4·A0 시4·A1 도♯5·A2 ‖ 레5·A3p1 … (레에서 손을 옮김)
```

교본에 나오는 운지 그대로입니다. 어느 줄로도 안 닿는 음은 **뺍니다** —
E현 1포지션처럼 위로 더 갈 줄이 없으면 음계가 짧아집니다. 그게 맞습니다.

## 순서도는 주석에서 자동으로 나옵니다

모든 소스에 `#|` 로 시작하는 **흐름 주석**이 달려 있습니다.

```bash
python3 flow.py                          # 화면에 텍스트 순서도
python3 flow.py 순서도.md                 # 텍스트 + Mermaid 코드
python3 make_flowchart.py 플로우차트.html  # 그림으로 구운 플로우차트 (70장)
python3 features.py                      # 화면에 기능 표
python3 features.py 기능리스트.xlsx        # 기능 목록 엑셀 (시트 4장)
```

**하나의 주석에서 세 가지가 나옵니다.**

```
   소스의 #| 주석 (파이썬)          ┌─→ 순서도.md        텍스트 + Mermaid
   화면의 //| 주석 (자바스크립트) ──┼─→ 플로우차트.html   그림 70장 · 오프라인
                                   └─→ 기능리스트.xlsx   기능 91개 · 모듈명 포함
```

그림을 따로 그리지 않으니 **코드와 문서가 어긋날 수 없습니다.**
`make_flowchart.py` 는 그림으로 굽는 데에만 `npm install mermaid` 와 playwright 가
필요합니다. 없으면 `flow.py 순서도.md` 로 같은 내용을 텍스트로 볼 수 있습니다.

| 태그 | 뜻 | 도형 |
|---|---|---|
| `#| 흐름` | 그 파일/함수를 한 줄로 | 제목 |
| `#| 구역` | 한 파일 안의 덩어리 나누기 | 원 |
| `#| 입력` | 들어오는 것 | 평행사변형 |
| `#| 단계` | 하는 일 | 사각형 |
| `#| 갈래` | `질문 ? 예 : 아니오` | 마름모 |
| `#| 반복` | 무엇마다 | 겹사각형 |
| `#| 호출` | `함수 → 받는 것` | 둥근사각형 |
| `#| 출력` | 나가는 것 | 평행사변형 |

**주석의 들여쓰기가 곧 계층**입니다. 반복 안쪽은 한 칸 더 들여씁니다.

코드를 고치면 주석도 같이 고치게 되고, `flow.py` 를 다시 돌리면 문서가 갱신됩니다.
그래서 순서도가 코드와 따로 놀 수 없습니다.

```

파랑  #5da9e9   ⊓ 다운보우  (그리고 "높게 벗어남")
주황  #d98b4a   ∨ 업보우
초록  #72b889   맞았음 · 1포지션
장미  #d96868   틀렸음 · 짚을 손끝
호박  #f0a02c   박자 주의     ← 골드보다 밝고 진하게. 헷갈리면 안 되니까

```

브랜드색이 인디고(`#4f46e5`)였는데 **골드**로 옮겼습니다. 지판이 나무색이고
줄이 황동색인데 버튼만 인디고면 따로 놉니다. 골드로 두면 사이드바 → 지판 →
줄이 한 계열로 이어지고, "일반 AI 서비스" 인상이 사라집니다.

**하나의 색이 두 가지를 뜻하면 안 됩니다.** 파랑을 "현재 음"으로 쓰자는 제안이
있었지만 파랑은 이미 다운보우입니다. 바이올린에서 활 방향은 손가락만큼 중요해서,
색을 뺏기면 정보가 사라집니다. 그래서 **뜻은 그대로 두고 세기만 낮췄습니다.**

| | 전 | 후 |
|---|---|---|
| 판정선 | `#ff2d45` 글로우 9 | `#8fa6b8` 글로우 5 |
| ⊓ 다운 | `#3987e5` | `#5da9e9` |
| ∨ 업 | `#d95926` | `#c9814a` |
| 악보 | `#e8e6e0` | `#e8e5dc` 아이보리 |

판정선은 세 번 갈아입혔습니다. 빨강은 화면에서 제일 먼저 눈에 띄어 "뭐가
잘못됐나" 싶었고, 금색은 **줄 색(`#f6e9b8`·`#f0d98c`)에 묻혀 사라졌고**,
산호색은 여전히 빨강으로 읽혔습니다. **회색-파랑**이 나무·황동 계열과 안 겹치면서
오류로도 안 읽힙니다.

**현재 음은 두 채널로 표시합니다** — *어느 음인가*는 커서 상자(늘 같은 모양),
*어느 활인가*는 색(파랑 ⊓ / 주황 ∨). 악보와 지판이 **같은 `n.color`** 를 쓰므로
둘은 언제나 같은 색입니다. 색이 번갈아 보이는 건 데타셰라서 활이 번갈아 나가기
때문이지, 표시가 흔들리는 게 아닙니다.

색을 바꿀 때 **`.streamlit/config.toml` 도 같이** 고쳐야 합니다. 안 그러면
슬라이더·체크박스처럼 스트림릿이 직접 그리는 것만 옛 색으로 남습니다.

## 가로축이 두 개인 문제

이 앱에서 가장 어려웠던 설계 문제입니다.

| | 가로가 뜻하는 것 |
|---|---|
| **악보** | 박자 (음이 같은 간격) |
| **지판** | 거리 mm (음높이 순서) |

올라가는 음계는 둘의 순서가 **우연히** 같습니다. 내려가는 음계는 정반대이고,
음이 뛰면 아예 뒤죽박죽이 됩니다.

**답: 축을 섞지 않습니다.**

```
   악보   라  솔♯ [파♯] 미  레  도♯ 시  라     ← 시간 순서
                   ↑ 지금 이 음만 색이 바뀌고 동그라미가 켜집니다
   ─────────────────────────────────────────
   노드              ▓                        ← 처음부터 끝까지 곧게
                     │                           (지판 자리에서만)
   ━━━━━━━━━━━━━━━━━━┿━━━━━━━━━━━━━━━━━━━━  판정선 + 리셉터
   지판   라  시 도♯ 레  미 [파♯] 솔♯ 라       ← 거리 순서
```

- **노드는 지판 자리에서 곧게** 떨어집니다. 어디에 앉을지 항상 예측됩니다.
- **"악보의 어느 음인가"는 악보에서** 알려줍니다 — 그 음표만 활 방향 색으로 바뀌고,
  뒤에 동그라미가 켜지고, 계이름이 굵어지고, 상자가 둘러집니다.
- 그래서 내려가는 음계에서도 헷갈리지 않습니다. 악보에서 색이 켜진 음을 보고,
  아래에서 곧게 떨어지는 노드를 짚으면 됩니다.

> 한때 노드가 악보 자리에서 출발해 지판 자리로 흘러내리게 해 봤습니다.
> 두 축이 이어져 보이긴 했는데, **어디에 앉을지 예측이 안 돼서 오히려 헷갈렸습니다.**
> 리듬게임이 레인을 고정하는 데는 이유가 있습니다.

## 어떻게 돌아가는가

### 1. 주파수 → 지판 위치

```python
mm = L * (1 - f_open / f)        # L = 328mm (4/4 진동현)
```

줄의 진동수는 진동 길이에 반비례합니다. 검산: 한 옥타브 위는 정확히 줄의 절반.
`f_open`만 바꾸면 네 줄에 그대로 적용됩니다.

### 2. 어디서 손을 옮길지

한 음씩 따로 보면 안 됩니다. **음계 전체를 보고** 정합니다.

1포지션으로 끝까지 닿으면 안 옮기고, 안 닿으면
**3포지션의 1번 손가락 자리**(개방현 + 5반음)에서 옮깁니다.
그 자리가 바로 1포지션 3번 손가락이 짚던 자리라서,
**짚어 보고 소리로 확인한 뒤** 올라갈 수 있습니다.

### 3. 소리 → 숫자 (YIN)

파형을 τ만큼 밀어 자기 자신과 겹쳐 봅니다. 한 주기만큼 밀었을 때 가장 잘 맞으므로
그 τ가 주기입니다. 자기상관만 쓰면 옥타브를 자주 틀리므로
YIN의 **누적 평균 정규화**로 낮은 τ에 불이익을 주고,
**포물선 보간**으로 정수 τ 사이를 메웁니다 (안 하면 센트 단위 정밀도가 안 나옵니다).

정확도: 순수음에서 오차 0.3센트 / 편차 0.03센트. 8초 분석에 0.1초.

### 4. 음 나누기

BPM을 아니까 각 음의 시간이 **이미 정해져 있습니다.**
첫 소리가 난 자리만 찾으면 나머지는 계산으로 맞습니다 — 정렬 문제가 사라집니다.

음의 **가운데(18%~88%)만** 씁니다. 앞은 활을 걸며 자리를 잡는 중이고,
뒤는 다음 음으로 넘어가는 중이라 아직/이미 그 음이 아닙니다.
이걸 안 자르면 옆 음이 섞여 **편차가 실제의 대여섯 배**로 나옵니다.

### 5. 평균과 표준편차를 반드시 나눈다

| | 뜻 | 처방 |
|---|---|---|
| **평균** | 손가락 자리가 틀림 | 짚는 위치를 옮겨라 |
| **표준편차** | 활이 흔들림 | 롱톤 연습을 해라 |

둘을 합치면 "20센트 틀렸다"밖에 안 나오고, 무엇을 고쳐야 할지 알 수 없습니다.

### 6. 박자는 첫 음 기준의 상대값

녹음을 언제 시작했는지는 연주와 상관없습니다.
첫 음을 0으로 놓고, 나머지가 그보다 빨랐는지 늦었는지를 봅니다.

### 7. 메트로놈 '똑' 을 첫 음으로 착각하지 않기

카운트인 소리가 마이크에 섞이면, 가장 이른 소리를 그냥 쓰는 방식은
**'똑'을 첫 음으로 잡아** 악보 전체가 한 박 밀립니다.

그래서 두 가지를 봅니다.

1. **충분히 이어지는가** — '똑'은 0.1초도 못 갑니다 (기준: 한 박의 28%)
2. **첫 음과 비슷한 높이인가** — 아니면 다음 소리 덩어리를 봅니다

검증: 앞에 2초 침묵 + 4박 메트로놈을 붙인 녹음에서 `t0 = 5.966초`
(정답 6.0초), 결과 지표는 깨끗한 녹음과 동일.

## 저작권에 대해

이 앱은 악보를 **불러오지 않습니다.** 기본 연습은 음계(저작물이 아님)이고,
그 밖에는 사용자가 직접 적거나 자기가 가진 악보를 찍은 것만 씁니다.

- 사진은 **저장하지 않습니다** — 인식할 때 한 번만 쓰고 그 자리에서 버립니다
  (디스크에 안 쓰고, 로그에 안 남기고, 결과 텍스트만 남깁니다)
- 인식 결과를 **공유·배포하는 기능이 없습니다**
- 기본 제공 곡은 퍼블릭 도메인만 넣을 예정입니다

다만 「저장만 안 하면 괜찮다」는 아닙니다. 한국 저작권법 제30조(사적이용을 위한 복제)는
**① 영리 목적이 아닐 것 ② 개인적으로 또는 가정 및 이에 준하는 한정된 범위** 를
같이 요구합니다. 유료화하면 ①이 흔들리고, 사진을 서버로 보내 처리하면
"복제의 주체가 누구인가"라는 별도의 논점이 생깁니다.
그래서 위 설계는 **위험을 줄이는 장치이지 면책이 아닙니다.**
(저는 변호사가 아니며, 서비스로 내놓기 전에는 전문가 확인이 필요합니다)
